# v2.5.4 → v2.5.5 — 白屏：GPU 级联后不再永久白着；崩溃第一次能查到原因

这一版只做两件事：**把一次真实白屏的根因修掉**，以及**让下一次崩溃留下能定位的证据**。
没有新功能，没有协议变化。

## 白屏的根因：`clean-exit` 被当成了"正常退出"

现场（`~/.ai-browser/logs/stderr.log`，2026-11-09 16:36:43）：

```
ERROR:command_buffer_proxy_impl.cc(324) GPU state invalid after WaitForGetOffsetInRange.
[index] tab render-process-gone: clean-exit     ×9
ERROR:network_service_instance_impl.cc(613) Network service crashed, restarting service.
```

GPU 的 command buffer 失效后，Chromium 把**全部渲染进程**按 `clean-exit`（exit_code=1）
在同一毫秒结束掉。而自救逻辑里有一行：

```js
if (reason === 'clean-exit') return;   // 认为是正常退出，不管
```

于是 9 个标签一个都没重载 —— 用户看到的是永久白屏。更糟的是此时工具层还在"说没事"：
`list_tabs` 报 `state:"ready"`，`paint_check` 报 `blank:false, verdict:"no-frame"`，
`ui.evaluate` 每个都要空等 5 秒才超时（target 已经死了，CDP 命令不返回）。

判据改成「**这一页还在不在我们手里**」：只有 tab 已被 `closeTab` 从表里摘掉、或
`webContents` 已销毁，才算正常退出；其余一律按非自愿终止重载（仍受原有 15 秒单次上限约束，
不会变成反复闪）。

## 崩溃第一次能查到原因

在这之前，崩溃现场是**拿不到**的：

- V8 的 native fatal 在 C 层直接写 fd 2，JS 的 `uncaughtException` 接不住；而启动器把
  stdio 接到短命管道上，读端一消失原文就丢了。
- 现在 `scripts/start.cjs` 与 `scripts/ensure_running.cjs` 把 fd 2 重定向到
  `~/.ai-browser/logs/stderr.log`（>5MB 自动轮转）。下次崩，`FATAL ERROR: ...` 就在那儿。
- 每 5 分钟一条 `heartbeat`（rss / heap / heap_limit / 标签数），启动一条 `runtime`，
  并自动检测"上次是不是没走 shutdown"（`previous_run_no_shutdown`）——
  回答"崩之前内存是不是在爬"。
- **多个渲染进程同时退出**会额外落一条 `render_cascade`（count / tabs / reasons /
  exit_codes + 指向 stderr 的提示）。这次事故只留下 19 条各自独立的记录，事后要靠
  stderr 才认出是级联。
- 日志**自己写不进去**时不再沉默：`ui.errors` 里会带 `write_error{code, message, count}`，
  同时往 stderr 打一行。这次日志文件从崩溃那刻起一条都写不进去，而原因被 `catch` 吞掉了。

## 顺带

- `platformVersion` 不再用「Darwin 大版本 − 9」推算。macOS 15 之后 Apple 把版本号跳到
  26/27，旧公式会算出 **`18.0.0`**（macOS 从没有 18）—— 风控脚本一读就是"自相矛盾的客户端"。
  现在优先用 `process.getSystemVersion()`，本机实测 `27.0.1`。
- `_lastMainUrl` 补登记进 `shared/tab_state.cjs` 的 `PER_TAB`：它是 per-tab 容器，
  漏清会让新标签继承上一任的"上一页"。

## 这一版首次补齐 macOS 产物

v2.5.3 / v2.5.4 的 GitHub Release 只有 Windows 安装器，**没有 macOS dmg**，npm 也一直停在
2.5.2。这一版把 macOS（arm64 dmg）、Windows（NSIS Setup.exe）、npm、GitHub Release 补齐。
