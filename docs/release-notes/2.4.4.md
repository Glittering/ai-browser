# v2.4.4 — 复核后补齐：监听幂等 / 监听失败可观测 / 打包闸门

这一版是**复核**的产物：另一轮会话提交了 Bug 5–8 的修复（方向对），但其中三项
没有真修好，四条回归全部是源码字符串匹配、证伪不了缺陷。逐条补齐，并把判据
换成能跑真实行为的断言。

## Bug 7：切回旧标签页会把导航监听再挂一遍（真缺陷）

地址栏跟随的挂载守卫是 `if (navStateWc === wc) return`，只挡住"连续两次切到同一
个 tab"。**A→B→A 切回来时旧对象没销毁，于是又挂一遍**：

```
切 5 轮后：A 上 did-navigate 监听 = 3，B = 2（应各为 1）
每次导航 pushNavState 被调 3 次；翻过 10 个还会触发 MaxListenersExceededWarning
```

这段逻辑原来写在 `index.js` 的闭包里，判据只能 grep 源码（"出现 removeListener
就算对"），所以上面这个真实缺陷在回归里**一直是绿的**。

现在抽成 `src/shared/nav_follow.cjs`：用 `WeakSet` 记账，同一个 webContents
**幂等**挂载；`destroyed` 时清掉持有的引用。`index.js` 只留一行接线。

## Bug 6：端口被占时一声不响（比崩溃更难查）

`ws_server` 把 `ready` 的 rejection 用 `.catch(() => {})` 吞了。实测两个实例
（不同 userData、同端口）时，第二个照常起窗口，但**没有 WS、没有一行报错、
`error.jsonl` 里只有 boot**。用户看到"窗口开着但什么都不响应"，agent 连不上，
两边都查不出原因。

- 监听失败 → 落盘 `ws_listen_error`（带端口、错误码、下一步）+ 一行带可执行
  建议的日志 + `index.js` 弹横幅（`EADDRINUSE` 会明说"先关掉另一个实例，或用
  `AI_BROWSER_PORT` 换端口"）。返回体新增 `listenError`，调用方不再靠猜。
- 第二个实例退出分支补 `recordError('second_instance_exit')`：从 Finder 启动时
  stderr 是黑洞，只 `console.error` 等于什么都没留下。

真机对照（`tools/_oneoff/verify_single_instance.cjs`）：

| | 第二个实例 | 第一个实例 |
|---|---|---|
| 已发布 v2.4.3（旧代码） | **不退出**（两个实例并存） | 存活 |
| 本次源码版 | `code=0` 干净退出 | 存活，关掉后可重启 |

## Bug 8：黑名单在删依赖自己的代码

`IGNORE` 是按路径删文件的黑名单，而顶层目录名用的是「任意层级」匹配。于是
`dist` 会把**依赖自己的 `dist/`** 一起删掉。实测已发布 v2.4.3 的 `app.asar`：

```
@modelcontextprotocol/sdk : 677 个文件只剩 3 个（package.json / README / LICENSE）
ajv                       : 缺 337/466
hono                      : 缺 559/562
```

`prune` 认为这些是生产依赖要留着，黑名单却把内容删了 —— 包内依赖树不自洽，
构建照样报"成功"，只有真去 `require` 的那一刻才炸。今天没炸只是因为桌面入口
没 import 它们。

两处改动：

1. **顶层名单锚死**：`^\/?(...)(\/|$)`。前导 `\/?` 不能省 —— packager 传进来的
   路径是带前导分隔符的（`/outputs/x.png`），只写 `^` 会让整条规则**静默失效**
   （实测体积从 12.5MB 涨到 89MB，`outputs/` 的取证截图全打进包里了）。
   `node_modules` 的剔除项单独一条，只剔构建工具链/纯类型/测试依赖。
2. **新增 `scripts/verify_asar.cjs`**：打包后与源 `node_modules` 对照，
   「入口文件被删」或「运行时文件塌缩过半」就 fail 构建。两条判据都必须与源对照
   才准 —— 有的包（如 `@modelcontextprotocol/sdk` 1.29）自己的 `package.json`
   声明的根入口根本没发出来，只发子路径，那不该算我们的账。
