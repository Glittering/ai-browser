# v2.4.6 — 文档：`chat` 不存在，浏览器也不会「用完自动关闭」

这一版**没有改任何运行时代码**，只修两处会主动误导 agent 的表述。起因是有 agent 把文档里的
"ask the user in chat" 读成一个叫 `chat` 的指令去调用，还困惑它是不是用完自动关闭。

## 事实先摆清

- **没有 `chat` 指令**：17 个 MCP 工具全是 `browse_*`，40 个 RPC 全是 `ui.*`，CLI 子命令是
  `start/gui/mcp/skill/call/status/ensure/version/help`；git 历史 `-S"chat"` 也没有过。
- **不会用完自动关闭**：首次调用自动拉起 Electron，关闭只由 `browse_quit` → `ui.quit` 触发。
  你不关它就一直开着（登录态在 `persist:ai-browser` 里长期保留）。
- 至于"用完即关"真正成立的那件事：MCP stdio server 进程随客户端会话结束退出 —— 它**带不走浏览器**。

## 改了什么

**1. 交接 = 在自己回复里说一句话，不需要工具**

`skills/ai-browser/references/tabs.md` 新增「怎么"说一句"——不需要任何工具」：回复里写一句人话、
结束这轮等回话、收到"好了"用 `browse_get_tree` 确认；并点名本项目没有 `chat` / `message` /
`ask_user`，也没有"一次性会话"，去调宿主的临时对话只会白绕一轮（它关不关与你无关）。
附带两条硬规则：人操作时不要 `browse_quit`；不要编造密码/验证码。

**2. 入口 SKILL.md 只加一句断言，不超冷启动预算**

入口文件原本是 2597 B，闸门上限 2600 B，只剩 3 字节。因此只在「需要人帮忙」里把话压成一行：
`无 chat/一次性会话工具`（实测 2598 B，仍在上限内）。详细契约放在按需加载的 `tabs.md`，
入口只留判据 —— 这也是这个文件一直以来的分工。

**3. 订正"用完自动关闭"这句错的营销文案**

`docs/marketing/PROMO_CN.md` 的推荐 prompt 原写"第一次调用会自动启动 Electron 浏览器，用完自动关闭"，
与实现不符，改成"任务做完调 `browse_quit` 关闭（你不关它就一直在）"；同一篇 78 行本来就写着
"用完用 `browse_quit` 释放"，前后矛盾已消除。`PR_BILIBILI.md` 同步。

**4. 其余交接文档统一口径**

`README.md`、`README-CN.md`、`llms-install.md`、`examples/AGENT_INSTRUCTIONS.md` 统一为
"自己回复里说一句 / no chat tool available"。

## 闸门

新增 `tests/test_skill_tool_refs.js` 三条（H-1/H-2/H-3），三条都做过阳性对照：

| 闸门 | 内容 | 阳性对照 |
|---|---|---|
| H-1 | 注册表里不得出现 chat/message/ask 类工具（MCP 与 RPC 两处都查） | 往 `MCP_TOOLS` 塞 `browse_chat` → 红并指名 |
| H-2 | 四份交接文档必须写明"没有 chat / 别调一次性会话" | 删掉 tabs.md 的断言 → 红并指名该文件 |
| H-3 | 文档里不得出现 `chat {...}` 这类调用形态 | 追加一行 `chat {"text":"hi"}` → 红 |

H-2 只认否定式断言（`没有 chat`），不认"提到 chat"就通过 —— 否则写给 agent 的正确做法会顶包。
匹配前先剥掉 markdown 的 `**` 和反引号（第一版就因为这把自己的正确写法判红了）。
