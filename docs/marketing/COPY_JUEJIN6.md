## 标题

AI 点不动网页按钮？八成是它根本"看不见"页面

## 正文

## 一个每天都在发生的误会

你让 AI 点一个网页按钮，它点了三次，按钮纹丝不动，最后回你一句"任务失败"。很多人的第一反应是：这模型不行。

其实多数时候，模型是被冤枉的——**它压根"看不见"页面。**

## 知识点一：截图是像素，语义树才是结构

浏览器渲染出来的画面是像素。人看着直观，模型读着费劲：它得从一堆像素里反推"这里大概是个按钮"。

而浏览器内部还有一棵 DOM 树和可访问性（Accessibility）语义树，每个节点明确写着：我是什么角色、叫什么名字、能不能点、在哪个位置。这才是给"机器"看的信息。

所以别急着问"为什么它点不准"，先问自己：**我给它的是像素，还是结构？**

## 知识点二：React 受控输入，直接改 value 是没用的

一个 90% 的人都会踩的坑：

```js
// 看似生效，实际组件毫无反应
input.value = "hello";
```

React 受控组件的值由 state 驱动。要让组件"收到"，必须走原生 setter 再派发事件：

```js
const setter = Object.getOwnPropertyDescriptor(
  HTMLInputElement.prototype, "value"
).set;
setter.call(input, "hello");
input.dispatchEvent(new Event("input", { bubbles: true }));
```

不知道这个细节，Agent 的"打字"就是空气打字——界面上毫无反应，任务必然失败。这也是很多"AI 操作网页"演示翻车的真实原因。

## 知识点三：正确姿势是「读树 → 拿 ref → 点 ref」

把流程串起来：先读语义树，拿到目标节点的稳定 ID（ref），再对这个 ref 执行点击或输入。坐标变了无所谓，ref 跟着节点走，页面小改版也打不散它。

我自己用的开源工具 ai-browser 就是这个思路：`ui.get_tree` 拿树、`ui.act` 点 ref，窗口全程可见，出问题人随时接管。npm 上一装就有，这里不展开。

---

记住这个知识点：**下次 Agent 点不动页面，先检查它拿到的是截图还是语义树。**
