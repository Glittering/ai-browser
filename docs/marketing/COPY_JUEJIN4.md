## 正文（约 2200 字，可直接粘贴）

八个平台，八种编辑器。CodeMirror、Draft.js、ProseMirror、CKEditor、Tiptap、contenteditable，还有一个跨进程 iframe。正常思路是给每个平台写一套自动化，八套脚本各坏各的，平台一改版全部返工。

我一套都没写。**这篇文章，就是零行适配代码发出来的。**

对，不用写稿，不用调格式，不用逐个后台登录。选题、写稿、分发、回收数据，全程是 agent 干的，我只在扫码和滑块验证时出场。

---

## 一、八种编辑器，一套路由

每次遇到一个新页面，它不猜。一次 `browse_capabilities` 先报告这页提供什么，然后选路：

- **L1**：页面自己暴露了数据模型 → 直接读写 JSON，最省；
- **L2**：语义树里有足够元素 → 按角色定位，按稳定 ID 驱动；
- **L3**：什么都不给 → 才退化到指针手势，并且必须用前后快照对比兜底。

八个平台全落在同一套路由里，没有任何一家的代码是为它单独写的：

| 平台 | 编辑器 | 路由 | 结果 |
|---|---|---|---|
| 掘金 | CodeMirror | L2 | ✅ 已发 |
| 知乎 | Draft.js | L2 | ✅ 已发 |
| CSDN | CKEditor + md 导入 | L2 | ✅ 已发 |
| 头条 | ProseMirror | L2 | ✅ 过审 |
| B站 | 跨进程 iframe | L2 + 窗口挂载 | ✅ 视频 + 专栏 |
| 简书 | contenteditable | L2 | ✅ 已发 |
| 51CTO | 单选分类弹窗 | L2 | ✅ 过审（人工审核） |
| 开源中国 | Tiptap ProseMirror | L2 | ✅ 过审（人工复审） |

**定位参数用的是稳定 ID，不是可见文字。** 页面改版、按钮换位置都无所谓，ID 不变动作就不点空——这是八套脚本变成一套的关键。

输入走的是浏览器受信事件通道。Draft.js、ProseMirror、Quill、CKEditor 看起来完全不同，底层的输入事件是同一条路，所以不存在"为某个编辑器打补丁"。

## 二、发完只是上半场

数据回采是同一条链路的复用：每天早上让它把各平台的展现、阅读、点赞抓回来，落进一张表，我不用挨个后台点开看。

哪类标题接得住量，数据说了算，不靠猜。这篇的标题就是上一轮数据逼出来的改写——同一个选题，换结构再发一次，看推荐池的点击率差多少。运营做到后面，拼的就是这种可重复的验证。

## 三、你可以直接复现

不是什么复杂的编排平台，就一个东西：**ai-browser**——把你平时用的那个浏览器，直接变成 agent 可以操作的对象。登录态是你的，窗口是看得见的，遇到扫码和滑块你能随时接手，接完它继续往下跑。

把这段话复制给你的 agent：

```
帮我安装并配置 ai-browser 这个 MCP server，命令是：
npx -y @glittering0717/ai-browser mcp
装好之后告诉我怎么验证它真的能用。
```

装完先让它干一件事测试：

> 用 ai-browser 打开 https://github.com/Glittering/ai-browser，
> 如果需要登录的话，停下来告诉我。登录状态的话，给项目点个 star。

扫码和滑块这两步它替不了，也不该让它替——涉及身份的动作必须留给人。

（不想点 star 也完全可以，把网址换成任何一个你需要登录的后台页面，效果一样。）

平台边界说清楚：**dmg 只有 macOS arm64**；npx 这条路 macOS 和 Linux 实测跑通，Windows 还是 experimental，欢迎来试。遇到问题可以让你的 agent 直接解决，或者到 GitHub 反馈。注意别装错：npm 包名带作者 ID `@glittering0717/`，GitHub 仓库是 `Glittering/ai-browser`，两个不一样。
