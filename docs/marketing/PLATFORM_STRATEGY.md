# ai-browser 各平台运营方向（战略切换：0→1 种子用户 · 2026-10-28 重定）

> 本文是**决策级**运营方向书，供各平台 bot（小C/小金/小五/小源 + 另一工作区小知/小公/小红）直接照做。
> 写稿细则见 `PER_PLATFORM_PLAYBOOK.md`；铁律与发布纪律见 `MEMORY.md`；实时状态见 `team-board.md`。
>
> **北极星指标（全矩阵统一）= 找到并跑通真实场景的开发者数（目标 10），不是阅读/展现量。** 主编日报须汇报「种子用户漏斗」。

## 0. 战略总纲（本次切换的核心）

**已核验现实前提（2026-10-28 `gh api`）：** GitHub `stars=4` / `forks=0` / `open_issues=0` / 今日仍有 push → 项目处于**极早期、作者仍在推进**的阶段。

**因此运营目标从「大规模曝光 / SEO 铺量」切换为「0→1 找 10 个真实用户」。** 4 Star 阶段最大的风险不是没人知道，而是把精力花在错的人身上。browser-use 早期增长复盘：*early growth came from building and talking to users*，大规模 storytelling 是后期的事。

**招牌主张（差异化定位，必须贯穿所有内容）：**
> 需要**登录态 + 有验证码 + 但不想让 AI 靠截图瞎猜**的自动化。
> 我们的独特组合 = **可见的真人窗口 + 语义树驱动 + 人随时接管 + 不碰截图**。
> 这是 browser-use 类纯 headless 方案最头疼、而我们天然解决的问题（用户原话：「扫码和滑块你能随时接手，接完它继续往下跑」）。

**三阶段路线图：**
- **阶段一（0→50 Star）：** 找到 10 个有真实「登录态 + 反爬 + 多平台后台」需求的人，让他们跑通、给反馈、在 README 留痕。**不做大规模营销。**
- **阶段二（50→500 Star）：** 把「人在回路」做成有争议性的清晰主张（叙事）——对比视频、技术博客、Show HN。
- **阶段三（500+）：** 生态化（路由插件、场景共建群、把语义树 + `browse_diff` 抽成独立 MCP 工具包）。

## 1. 内容生产策略（2026-10-28 用户五条原则 · 全平台统一执行）

> 这是内容「角度」层的总纲。无论哪条平台线、哪个 bot，写稿都先过这五条。

### 1.1 平台调性必须匹配（不一套稿发全网）

每个平台读者不同、文风不同，硬搬会被限流/没人看。速查：

| 平台 | 读者画像 | 调性 | 适合的内容形态 |
|---|---|---|---|
| CSDN | 工程师、搜索流量为主 | 实操 / 避坑 / 对比，SEO 长尾词 | 教程、清单、踩坑复盘 |
| 掘金 | 初中级工程师、爱新鲜 | 工程复盘 / 数据 / 观点鲜明 | 实测对比、踩坑清单、技术观点 |
| 51CTO | 企业运维 / 开发管理者 | 企业落地、稳重、有背书感 | 一次落地实践、架构取舍 |
| OSChina | 开源理想主义者 | 原理 / 为什么这样设计 / 社区感 | 设计取舍、求试用帖 |
| 知乎 | 高知、爱质疑、重逻辑 | 回答态、用真实案例说话、有冲突感 | 高关注问题下的硬核回答 |
| 小红书 | 普通用户、短平快、重真人 | 经验 / 种草 / 踩坑，配图优先 | 第一人称「我试了」短笔记 |
| 公众号 | 私域、深度读者 | 长文、有观点、有温度 | 项目进展、深度方法论 |

**跨平台必须重写（铁律），且重写要改「调性」不是只改词**——同一件事在 CSDN 是「教程」，在小红书是「我踩的坑」，在知乎是「回答一个真问题」。

### 1.2 内容配比：不要每天都是纯推广文

| 类型 | 占比 | 是什么 | 作用 |
|---|---|---|---|
| **硬技术科普** | ~20% | 讲某个功能**怎么实现的、逻辑怎么回事、为什么这样设计、带来什么效果**（带源码/原理图/实测数据） | 立信任的锚，证明「不是嘴炮」 |
| **有意思、别人愿意看的文** | ~60% | 故事化 / 场景化 / 有观点 / 有冲突，**软广自然融入**（不硬塞，案例里顺带带出「我用的就是这个工具」） | 主流量来源，让人愿意看完并转发 |
| **热点二创** | ~20% | 见 1.4，找热帖做二次创作 | 借势流量，破冷启动 |

**禁止：**
- 开头就「我做了个 XX 求 star / 求关注」的纯推广文；
- 通篇功能清单、通篇外链 CTA；
- 同一篇稿换个标题发遍全网（跨平台必须重写调性）。

**软广自然融入的写法（关键）：** 把 ai-browser 当成「我这次用来解决问题的工具」来写，而不是「我要安利的产品」。例如写「我用语义树把 8 个平台的编辑器都打通了，没为任何一家写适配」，读者读完觉得「这思路有意思」，软广已经种进去了，比结尾硬塞 CTA 强十倍。CTA 块（链 examples + 邀找真实场景）保留，但**只放在硬技术/二创类文末，有趣类文末用一句话顺带即可**。

### 1.3 利用平台自身的流量扶持

每个平台都有官方给新作者的流量入口，bot 写稿前要**先看一眼再动笔**：
- **创作者中心活动 / 新星计划 / 流量包**：掘金创作者活动、知乎创作中心打卡/活动、小红书话题活动、头条/抖音热榜、B站活动——参与即拿基础曝光。
- **热搜话题 / 热门事件**：蹭热点时，把 ai-browser 作为「我用来验证/操作这个热点相关网页」的工具自然带出（如某平台改版 → 「我用语义树对比了改版前后的 DOM 差异，比截图清楚」）。
- **平台内话题 / 标签流量**：掘金话题、知乎话题、小红书话题——发文挂对话题才有基础分发（掘金同话题二篇起限流，故需**换话题**）。

**动作：** 每条内容生成前，先 `browse_navigate` 到该平台创作者中心/热榜看一眼当前活动与热点，能蹭则蹭，并在看板注明「蹭了 XX 活动/热点」。

### 1.4 热点二创机制（好帖子 8-9 成相似 → 二创 + 观点 + 软广）

**原理：** 同平台高赞内容高度同构（8-9 成相似），原创从零写很难赢过已验证的热帖。正确做法是**找热帖做二次创作**，不是抄，而是：
1. **监控热帖**：平台热榜 / 高赞回答 / 高收藏文章 / 同行大 V 爆款。
2. **提炼「为什么火」**：情绪点（焦虑/爽点）、信息差、冲突感、实用度。
3. **二创**：保留其结构/钩子，换自己的真实案例 + 加自己的观点 + 用 ai-browser 跑一遍验证（形成独家素材）+ **自然融入软广**。
4. **发布**：挂对话题/活动，文末视类型决定 CTA 强度。

**例：** 某「我用 Playwright 自动化被验证码卡死」热帖（高赞）→ 二创《我也被验证码卡过，但换了个思路：把窗口留给人，滑块我划一下就过了》+ 用 ai-browser 跑一个真实接管 demo + 顺带点出「语义树不靠截图，所以改版也不怕」。

### 1.5 复盘要运营化（多维度，不是几个播放量）

**禁止**只报「阅读 X / 展现 Y」。主编日报按以下维度复盘，且每条给「下一步动作」：

| 维度 | 看什么 | 指导意义 |
|---|---|---|
| 种子用户漏斗 | Issue/评论/私信咨询数 + 场景质量 | 北极星进度，比阅读重要 |
| 内容互动质量 | 评论 sentiment、是否有真人讨论、**收藏率**（价值锚） | 内容是否真有用 |
| 热点蹭中率 | 蹭了几个热点/活动、带来多少增量 | 流量扶持利用得怎样 |
| 软广自然度 | 评论是否反感硬广、是否有人问「这是什么工具」 | 软广姿势对不对 |
| 平台权重趋势 | 分发量级走势、是否限流/折叠 | 账号健康度 |
| 流量来源结构 | 推荐/搜索/主页/外链占比 | 下一步重心（搜索弱就补 SEO，推荐弱就补互动） |
| 同题材对比 | 硬技术 vs 有趣文 vs 二创的完读/转化差异 | 配比要不要调 |

## 2. 各平台方向（基于上面 5 条 + 平台实测）

### 2.1 CSDN — SEO 长尾复利 + 场景筛选（最高产、最稳）
- **现状（实测）：** #5 读237/藏6、#4 读283、#2 走平263/3/5（10-26 回采）；匿名 curl 200 公开。唯一持续自然访问渠道。
- **方向：** 周更 1 篇 SEO 长尾，**每篇 = 一个具体场景的可复现解法**（如「用语义树给 Draft.js 自动灌文，不靠坐标」）。按 1.2 配比：硬技术为主（CSDN 读者要干货），偶尔做二创（如二创某「自动化踩坑」热帖）。结尾挂 CTA 块筛真实需求者，标题含真实搜索词。
- **节奏：** 小C 每周一 10:00，1500–3000 字。
- **判定线：** ① 24h 读>100、藏>5（SEO 复利）；② 带来真实 Issue/评论咨询 = 种子用户信号（核心 KPI）。

### 2.2 掘金 — 工程复盘 + 换话题破限流 + 二创主场
- **现状（实时 2026-10-28）：** #2 1668展现/81读/1赞（plateau）；#3 14展现/99读；#4 17展现/27读。同话题二篇起分发抑制。
- **方向：** ① **换话题 + 间隔≥7 天**硬前提；② 内容走「工程复盘 + 实测数据 + 踩坑清单」，开头给结论；③ **二创是掘金主战场**——找掘金/同行热帖二创（1.4 流程），加 ai-browser 实测验证；④ 发布后 30 分钟内自补一条「欢迎带场景来聊」的评论。
- **节奏：** 小金 每周日 10:00，1500–2500 字，挂「AI 编程」话题（仍限流则换话题并记录）。
- **判定线：** 展现≥1000 = 分发开关开；真实场景 Issue/评论 ≥1 = 阶段一达标进度。

### 2.3 51CTO — 企业读者落地实践背书
- **现状（实测 10-26）：** #3 读 13，公开。量级小但稳。
- **方向：** 每两周 1 篇「一次落地实践」（运维/开发视角），结构=问题→方案→环境→实操→踩坑→小结；**强调「企业内网 / 需登录的后台操作」场景**。可二创企业自动化类热帖。审核慢，留足 24h。
- **节奏：** 小五 隔周周三 10:00，1200–2000 字。

### 2.4 OSChina（开源中国）— 开源语境 + 求试用帖（阶段一主战场）
- **现状（实测 10-26）：** #3 读 69 / 互动 1，公开。
- **方向：** 每两周 1 篇「为什么这样设计」实现原理向（800–1500 字）；**周期性发「求试用/求吐槽」帖（不是求 Star）**。OSChina 是阶段一最合适的「找人」场，也适合二创开源圈热帖。
- **节奏：** 小源 隔周周五 10:00。

### 2.5 知乎 — 高权重但账号级折叠，无外链版 + 场景回答
- **现状（实时 2026-10-28）：** #3（已修三倍重复稿）`collapsed:false` ✅；#4/#5 不在问题首页首屏（与折叠态一致）；11-02 00:30 自动化 9f715d55 复查。
- **方向：** 写「回答」挂高关注问题（问题浏览≥1000 且回答数<20），**首发无外链版**，结尾 CTA 改为「有类似后台操作场景的，评论区告诉我」——既避免外链触发折叠，又筛人。**知乎回答是最适合二创的场**（高赞回答结构透明，二创 + 用 ai-browser 跑验证 + 自然带出）。
- **节奏：** 另一工作区「小知」每日 20:00（保留现状，等 11-02 复查后再评估是否改无外链版）。

### 2.6 公众号 — 私域沉淀（另一工作区）
- 深度长文 / 项目进展，真人视角；按 1.2 配比做「有趣 + 硬技术」混合，埋「找真实场景」钩子。每日 21:00（小公）。

### 2.7 小红书 — 真人视角种草/经验（另一工作区）
- 真人视角 + 话题规范，每日 12:30 主更 + 养号 3 次。**禁止 AI 身份**（血泪教训）。经验/踩坑/种草，配图优先。**二创友好场**：找小红书爆款笔记二创（换自己的真实案例 + 软广自然带出）。

### 2.8 头条 — 停放（待认证）
- 账号需**大陆身份证 + 今日头条 App 扫码**认证（用户本人操作）。认证后首条带「找真实场景」CTA，不以曝光为唯一目标；优先蹭头条热榜。

### 2.9 B站 — 停放（缺发布片）
- 用素材库 `demo.gif`/`demo_vertical.mp4`/封面图剪 1–2 分钟演示片（前 5 秒给结果画面 + 中文字幕），首条带「找真实场景」CTA；可蹭 B站活动。

### 2.10 SegmentFault — 放弃
- 登录改短信验证码 + 雷池 WAF 拦截，基本无解。精力集中到其他能跑的平台。
