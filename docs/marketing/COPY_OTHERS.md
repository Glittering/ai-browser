## 1. 51CTO 博客（实践向 · 约 1500 字）

**标题：**`不用截图也能让 Agent 操作网页：语义树方案的一次落地实践`

**正文要点：**
1. 起因：脚本最贵的不是写，是每次重新登录。
2. 现有方案盘点：Playwright MCP、chrome-devtools-mcp、Browser-use，各自断点在哪。
3. 落地路径：
   - 一个常驻可见 Electron 窗口，登录一次长期复用
   - 页面 → 语义树（role/label/value/states/actions + 稳定 ID）
   - 点击/输入走 CDP 受信事件，不是合成 JS 事件
4. 三个真实踩坑（可直接引用）：
   - Cmd+V 走 CDP 直达渲染器，合成键不触发原生粘贴 → 用 ClipboardEvent + DataTransfer(text/html) 派发 paste
   - `browse_evaluate` 不等 Promise，含 `await` 的 IIFE 返回 `{}` → 拆成"触发 → 等待 → 取结果"
   - 标签是 el-autocomplete，合成 `click()` 不吃 → `press ArrowDown` + `Enter` 受信选中
5. 验证：工具返回 success ≠ 世界改变了，必须让 diff 成为原语。
6. 边界与风险：只绑 localhost、无鉴权、首次 110MB。

## 2. InfoQ（投稿制 · 需过审 · 约 1800 字）

**标题：**`Agent 浏览器的三条技术路线：像素、DOM 快照与语义层，各自的成本边界在哪`

**为什么这样写**：InfoQ 不是产品发布渠道，它要"观点 + 案例 + 行业判断"。所以这篇**不出现安装命令**，只讲技术判断，项目只在"落地案例"里出现一次。

**结构：**
- 判断一：Agent 浏览器的分歧点不在"能不能点"，在"用什么当输入"——像素、DOM、还是语义层。
- 判断二：像素路线的成本结构不可持续（每步一张图 + 坐标脆弱）。
- 判断三：DOM 路线的真瓶颈是身份（登录态）而不是解析。
- 判断四：被低估的一环是"验证"——工具返回成功 ≠ 状态改变，这是自动化里最高频的故障放大器。
- 判断五：canvas 是被忽略的盲区；而它其实不需要 OCR，绘制调用层就有原始字符串。
- 收尾：短期不会有统一方案，选型应该按"是否需要真实登录态""是否涉及 canvas""是否需要可验证"三个问题来分。

## 4. SegmentFault（纯踩坑 · 零推广 · 约 1200 字）

**标题：**`CDP 直达渲染器时 Cmd+V 不触发：一次粘贴失败的完整排查`

**正文骨架：**
- 现象：程序化粘贴在普通 input 生效，在 Draft.js/ProseMirror 编辑器里丢失全部格式。
- 排查：合成 JS 事件 vs CDP Input 事件；浏览器进程加速键与渲染器的关系。
- 结论：合成键盘事件不经过浏览器进程加速键路径，原生粘贴不会被触发。
- 解法：合成 ClipboardEvent + DataTransfer(text/html) 派发 paste，让编辑器自己过粘贴管线。
- 验证：格式保留统计（h2 / 代码块 / 加粗 span / 列表项）。
- 结尾一句：同类问题在 canvas / iframe 上也有对应解法，见项目文档。

> 这篇**不推销**，纯技术债复盘——SF 用户最吃这个，也是唯一能自然带出我们工程深度的形式。
