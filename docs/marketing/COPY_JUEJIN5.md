## 标题

浏览器自动化，别把截图喂给 Agent

## 正文

## 先讲一个我自己的坑

我有个需求很简单：让 Agent 每天替我打开几个后台，把数据抄下来。这些后台有个共同点——**要登录态**，偶尔还弹滑块。

第一版方案我用的是无头浏览器：跑起来确实不用人管，但第二天早上看日志，它卡在登录页上，对着截图反复猜按钮坐标，点了十几次，一次都没点中。页面改版过一次，它之前"记住"的位置全废了。

折腾下来我想明白一件事：**问题不在模型不够聪明，在给它喂的"眼睛"不对。**

## 截图是给人看的，不是给模型看的

截图方案的死穴有三个：

1. **像素坐标是脆的**。页面一改版、窗口尺寸一变，坐标全废。模型不是看不懂页面，是它只能"猜"像素后面的东西。
2. **烧 token 还慢**。每一步都要把图传给模型看一遍，一张 1080p 截图几千 token，一个流程跑下来，token 账单比招人还贵——这不是段子，最近热议的那篇"烧 token 成本"文章说的就是这事。
3. **错了没法接管**。无头模式跑飞了，你只能翻日志猜它刚才干了什么。

## 我现在给 AI 立了三条规矩

后来我把思路反过来，稳定多了：

**规矩一：不给截图，给结构。** 浏览器内部维护着一棵可访问性语义树，每个节点带着角色（按钮/输入框/链接）、名字、位置。让模型读这棵树，点的是稳定的节点 ID，不是像素坐标。页面改版，结构还在，判断照样成立。

**规矩二：窗口必须看得见。** 我不用无头模式。Agent 干活时窗口就摆在屏幕上，它点到哪我看得见，发现不对随时把鼠标抢回来。人随时能接管，这比"全自动"重要得多。

**规矩三：验证码和扫码，留给人。** 涉及身份的动作不交给 Agent——它遇到滑块就停下来叫我，我划完它接着跑。这看着像"不够自动"，其实是边界：账号是我的，身份动作凭什么外包。

## 这套东西我开源了

这三条规矩最后长成了一个开源项目 **ai-browser**（Electron + CDP + MCP server）。MCP 客户端接上就能用：

```json
{
  "mcpServers": {
    "ai-browser": {
      "command": "npx",
      "args": ["-y", "@glittering0717/ai-browser@latest"]
    }
  }
}
```

macOS 和 Linux 上 npx 直接跑。它开着可见窗口，模型通过 `ui.get_tree` 拿语义树、用 `ui.act` 点节点，从头到尾不碰截图。
