## 正文

先直接回答：**大概率不是自主性太强，是中间态不可验收。**

这两个东西的信任结构其实不一样。深度研究是"一次交换"：你给一个问题，它跑一段（你看不见它在干嘛，但你知道它在查资料），最后还你一份带引用的报告。整个过程有明确的终点，而且结果本身自带验收性——引用对不对、结论站不站得住，你翻一遍就知道。

Agent 是"多步交换"：拆任务、调工具、看页面、点按钮、再拆下一步。问题就出在这——每一步都返回"成功"，但每一步的成功你都**没法当场验收**。它说点过了，页面真的变了吗？它说写入了，编辑器里真的有了吗？跑完十步，你面对的是一个黑盒累积出来的结果，中间任何一步错了都会滚进最后交付里。

人反感的一直不是"它自己动了"，而是"它动了但我不知道动到哪了"。

## 我自己的体验：从不敢放到敢放，改的不是自主性

我自己重度用一个 Agent 驱动的浏览器干活（具体出处放在最后）。最开始我也不敢放——让它去 8 个平台发布文章，它跑到第三个平台我就开始焦虑：前两个到底发出去没有？

后来我改的不是它的权限，是它的**可见性**，具体两件事：

**第一，每步操作前后各取一次页面快照，给出显式的"变了/没变"判定。** 点击回执说成功不算数，快照对比说 DOM 真的变了才算。定位也走语义树里的稳定 ID，不按按钮上的可见文字——平台前端一改版，按文字找的选择器会集体点空，按 ID 找的重新探一次就行。这一条加上之后，我的焦虑少了一大半——不是因为我更信任它了，是因为我可以**抽查**了。信任从"信仰"变成"可验证"，这是完全不同的两种东西。

**第二，涉及身份的动作，它跑到就停。** 扫码、滑块、验证码，它不碰，停下来告诉我"该你了"，我做完说继续，它接着跑。这条听起来是限制，实际上是我敢让它跑长任务的前提——因为最危险的那几步恰好是它明确不碰的几步，剩下的机械步骤出错也有快照兜底。

自主性我一点没减，该它规划的它规划，该它点的它点。变的是：每一步可抽查，危险步有人守着。

## 那"自主性太强"这个感觉是哪来的

我觉得是**边界切错了位置**。常见切法是按"步骤复杂度"分：简单的它自己干，复杂的问人。但更合理的切法是按**验收成本**分：

- **规划层**可以尽量自主。先做哪步、失败了重来还是跳过，这种决策人有快照和日志兜底，验收成本低——它爱怎么规划怎么规划。
- **执行层**要可抽查。每步带前后对比，错了当场能抓。
- **身份层**必须是人。登录、扫码、验证码，这不是"信不过 AI"，是这些动作的意义就在于"人确认过"。

按这个切法，"自主性太强"的感觉会消失，因为强的那部分正好是你不需要盯的那部分。

## 出处

上面这些是我在开源项目 ai-browser 里做 Agent 自动化时的真实设计（MIT，GitHub 搜 Glittering/ai-browser）：一个 Agent 驱动的可见浏览器，17 个 browse_* MCP 工具，语义树输入 + 受信操作 + diff 验证。想试的话，最小验证任务是打开项目主页，需要登录就让它停下来你来，登录状态的话顺手点个 star——一次验证打开页面、读懂结构、点击生效。不想点 star 也完全可以，换成任何需要登录的后台页面，效果一样。

边界照旧：dmg 只有 macOS arm64，npx 方式 macOS 和 Linux 实测跑通，Windows 还是 experimental。

你们用 Agent 的时候，卡在"不敢放"还是"放了不放心"？我感觉这两个的解法完全不一样。
