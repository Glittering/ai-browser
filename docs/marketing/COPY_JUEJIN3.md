## 一、我如何复刻使用？

不是什么复杂的编排平台，也没写一堆爬虫脚本。就一个东西：**ai-browser**。

它做的事很朴素——**把你平时用的那个浏览器，直接变成 agent 可以操作的对象**。登录态是你的，窗口是看得见的，遇到扫码和滑块你能随时接手，接完它继续往下跑。

仓库在这里：https://github.com/Glittering/ai-browser

## 二、安装命令

把这段话复制给你的 agent 就可以：

```
帮我安装并配置 ai-browser 这个 MCP server，命令是：
npx -y @glittering0717/ai-browser mcp
装好之后告诉我怎么验证它真的能用。
```

现在 mac 和 linux 跑得挺顺，win 还在测试——不过暂时看还好。遇到任何问题，都可以让你的 agent 直接解决，或者到 GitHub 给我反馈。欢迎一起开发。

（注意别装错：npm 包名带作者 ID `@glittering0717/`，GitHub 仓库是 `Glittering/ai-browser`，两个不一样。）

## 三、安装完了，先让它干件事测试

现在你已经装完了项目，把这句话复制给你的 agent，看看它强大的能力吧：

> 用 ai-browser 打开 https://github.com/Glittering/ai-browser，
> 如果需要登录的话，停下来告诉我。登录状态的话，给项目点个 star。

当然，如果需要登录的话，你还是要自己登录一下的——扫码和滑块这两步它替不了，也不该让它替。

（不想点 star 也完全可以，把网址换成任何一个你需要登录的后台页面，效果一样。）

## 四、它凭什么跨 8 种编辑器不用适配

每次遇到一个新页面，它不猜。一次 `browse_capabilities` 会先报告这页提供什么，然后选路：

- **L1**：页面自己暴露了数据模型 → 直接读写 JSON，最省；
- **L2**：语义树里有足够元素 → 按角色和文字定位，按稳定 ID 驱动；
- **L3**：什么都不给 → 才退化到指针手势，并且必须用前后快照对比兜底。

掘金（CodeMirror）是 L2，知乎（Draft.js）是 L2，B站那个跨进程 iframe 是 L2 加一次窗口挂载。八个平台落在同一套路由里——所以没有任何一家的代码是为它单独写的。

输入走的是浏览器受信事件通道，Draft.js / ProseMirror / Quill / CKEditor 走的是同一条路。
