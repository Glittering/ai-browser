# M0 · 总报告：产品、架构与 30 天路线图

> 基线：v2.4.5 · `src/` 67 文件 / 21.7k 行 · 单测 91 文件 / **1228 条全绿（23s）**
> 审计方式：只读。逐模块报告见同目录 `01`–`09`。**本轮未修改任何源码。**

## 1. 一句话理解这个项目

**AI Browser 是一个「给 agent 用的真浏览器」：窗口真实可见（人随时能接管），
但操作面只有两个——语义树读、受信输入点。它把「agent 怎么看见网页」从截图/OCR
换成了结构化树 + CDP，并把「动作到底生效没有」做成回执里的可判枚举。**

它解决的不是「自动化测试」问题，而是**长任务、真实站点、需要登录态**的 agent 操作问题：

| 传统方案 | 痛点 | AI Browser 的回答 |
|---|---|---|
| 截图 + 坐标点击 | 分辨率/缩放/遮挡/OCR 误差；模型无法可靠复现 | `data-ai-id` 句柄 + 语义树；坐标只作为兜底 |
| Playwright/Puppeteer 脚本 | 每个站点都要写选择器；登录/验证码要人肉 | 通用读层 + 真人可见窗口；人可扫码/滑块后 agent 继续 |
| Headless 浏览器 | 人无法接管；部分站点风控更严 | 真实 Electron 窗口，可手动操作 |
| 纯 MCP 封装 | 工具多、token 贵、错误语义模糊 | 17 个工具 + `effect_state` + `retry` 策略 |

**护城河**（真实存在、且难复制的三点）：

1. **「成功 ≠ 做成了」的工程化**：`effect_state` 三态、动作前后指纹、`page_coverage`、
   `frame_hints`、`paint_check`。这不是功能，是**可信度**。
2. **事故驱动的知识沉淀**：每个坑都有注释、回归、恢复指引（`1228` 条测试以事故编号命名）。
3. **人机共处的产品形态**：不造「协作协议」，只守护「窗口可见 + 可手动操作」这条不变量。

## 2. 架构全景（当前事实）

```
┌────────────────────────── agent / 人 ──────────────────────────┐
│  MCP stdio (17 tools)          WebSocket JSON-RPC (40 methods) │
└───────────────┬──────────────────────────────┬─────────────────┘
                │ mcp_server → mcp_ws           │ ws_server（route/deadline/错误落盘）
                └──────────────┬───────────────┘
                               ▼
                    PageManager（唯一状态持有人，5857 行）
        ┌──────────────┼───────────────┬──────────────────┐
        ▼              ▼               ▼                  ▼
   BrowserView     CDP Hub        Network/Canvas     Snapshot/Diff
   (每 tab 一个)   (debugger)      Download/Error     Paint/Blank
        │
        ▼
   preload: bridge.cjs ── extractor.cjs（DOM 语义树）
                        └─ actions.cjs（合成事件兜底）
                        └─ watcher.cjs（变更观察）
```

**分层评价**：`ws_server`（协议）→ `PageManager`（状态）→ `preload/shared`（纯逻辑）
三层方向正确；`shared/` 的「判据下沉」是整个可测性的基础。
**主要问题不在分层，而在两个边界**：`PageManager` 太大（无法独立演进），
以及**页面 ↔ 控制面没有信任边界**（P0，见下）。

## 4. 必须先修的 10 件事（按顺序）

| # | 级别 | 问题 | 报告 | 为什么现在 |
|---|---|---|---|---|
| 1 | **P0** | WS 无认证、不校验 `Origin`、允许 `tab` 跨标签 → 浏览器内任意网页可读所有登录态、任意执行 JS | M2 | 决定「用户敢不敢用它登录」；一行 Origin 检查即可先堵住 |

| 8 | **P1** | `PageManager` 5857 行零行为单测；CI 不跑 e2e | M3/M8 | 所有核心改动的回归只能靠人 |
| 9 | **P1** | 每次读树必合并 OOPIF + `wait` 每轮抽整棵树 | M4/M2 | 常见页面上读一次 = 多次跨进程；wait 名存实亡 |

## 5. 四个结构性主题（比单点 bug 更重要）

### 主题 A：把「机制」用在更多地方（本项目最擅长的事）

`shared/tab_state.cjs` 是教科书级修复：把「关 tab 要清哪些状态」变成数据 + 闸门测试，
新增容器忘登记就构建失败。**同样的模式可以复制到三处**：

1. **IPC 通道**：每个 `ai:*` 通道登记 `{sender 校验, 允许的 payload 形状}`，未登记 = 测试红；
2. **参数映射**：每个方法登记 `{schema 字段, 消费字段}`，漏抄 = 测试红；
3. **文档**：README 工具表/数量从 `MCP_TOOLS` 生成或断言，漂移 = 测试红。

### 主题 B：补上「单一事实源」

当前同一个事实有 3–5 份手写副本：WS switch、MCP schema、`mcp_args`、README、PLAN。
建议引入 `methods.js` 方法表（M2 P1-3），WS 分发 / MCP 声明 / 参数校验 / 契约测试全部由它生成。
这是**一次投入、长期免维护**的改造。

### 主题 C：把信任边界写成产品能力

当前安全模型是隐式的：「localhost + 无认证 + 页面能写 IPC + 无 sandbox」。
建议明确三层：

| 边界 | 规则 | 实现 |
|---|---|---|
| 页面 → 控制面 | 页面**永远不能**发起控制调用 | Origin 拒绝 + token / UDS |
| agent → 宿主 | agent 只能读页面，不能读本地文件（除非显式授权） | upload 白名单、evaluate 禁 Node、screenshot 路径白名单 |
| 人 → agent | 人可随时接管，但 agent 的工作不被误杀 | `before-input-event` 空闲信号、关窗确认 |

把这三条写进 `docs/SECURITY.md`，它本身就是**销售资产**：同类项目大多回避这个问题。

### 主题 D：默认开销要能被调用方看见

网络抓包、canvas hook、动作 probe、每读合帧，全部默认开。当前是「为了观测正确性付成本」，
方向没错，但缺少 `cost_ms / capture_status / frames_read / dropped` 这类**成本回执**。
建议把「这次调用花了多少、抓全了没有」变成回执的一部分，让 agent/人自己决定是否降级。

## 6. 30 天路线图

### 第 1 周：止血（只做安全与「说谎」）

| 任务 | 交付 | 验收 |
|---|---|---|
| Origin 校验 + 启动 token（或 UDS） | `ws_server` 连接拒绝 | 页面内 `new WebSocket(...)` 被拒；MCP 全绿 |
| 删除 `sendTree/sendDiff`，`ai:*` 校验 sender + 期望 tab | `bridge.cjs` / `page_manager` | 页面伪造 `id` 不再能 resolve |
| 禁止 preload eval 兜底 | `page_manager.evaluate` | CDP 不可用时返回 `cdp-unavailable` |
| upload 目录白名单 + 大小上限 | `upload` 前置校验 | `/etc/passwd` 被拒；`~/Downloads` 通过 |
| screenshot 路径限制到 `userData/screenshots` | `screenshot` | 任意路径写入被拒 |
| MCP per-call timeout | `mcp_ws.call` | `wait 20s` 不再 15s 超时 |
| 修 `subset/mode/focused_only` | 读层 | 三个参数都有可观测效果 |

**本周不做任何新功能。** 安全修复的验收必须包含「攻击用例」（页面内脚本）而不是只有 happy path。

### 第 2 周：让「承诺」与「实现」一致

- 建立 `methods.js` 方法表，先覆盖 17 个 MCP 工具（WS 可后续迁移）；
- 统一错误通道（`{ok, error:{code, retryable, hint}}`）+ 修 `id:null`；
- `README` 工具表由 `MCP_TOOLS` 生成；加 `test_docs_consistency`；
- `docs/ARCHITECTURE.md`（当前事实）+ 给旧 `PLAN_*` 加历史横幅 + 建 ADR 目录；
- CI 加 Linux 单测 + ESLint + `node --check`；选 2 个 e2e（`background/lifecycle`）进 CI。

### 第 3–4 周：还结构债（只做两件）

1. **拆 `PageManager` 的第一刀**：抽出 `TabRegistry` + `ViewShell` + `CdpHub`（不追求一次拆完），
   用假对象补 20 条行为单测（`newTab/closeTab/setActive/layout` 的失败注入）；
2. **拆读层第一刀**：`extractTree` 按判据拆文件 + 帧树缓存（`frameId+navigationSeq`），
   目标是带 3 个 iframe 的页面第二次 `get_tree` < 50ms。

其余（watchdog 输入信号、关窗确认、下载同名、布局单一函数、canvas 懒开启）
放在第 2 个月，按「是否影响信任/一致性」排序。

## 7. 不建议现在做的事

| 不建议 | 原因 |
|---|---|
| 继续加站点特化规则 | 读层覆盖率 33–60% 的根因是判据结构，不是规则数量；先把 `extractTree` 拆开 |
| 继续扩工具（>17） | `test_api_budget` 已经量出「每轮固定税」；新增能力优先合并进 `browse_tabs/act` |
| 全量 TypeScript 重写 | 21.7k 行、核心类未拆，重写会把「结构债」变成「迁移债」；先加 lint + JSDoc |
| 追 token 数继续砍描述 | 预算文件明确记录地板 ≈16KB；再砍是用错误率换数字 |
| 做「人机协作协议/控制权状态机」 | 产品定位已经明确：协作发生在对话里，浏览器侧不需要新协议 |

## 8. 产品层面的三个判断

1. **定位是对的，且比同类更克制。** 「不截图、真窗口、MCP 原生、人可接管」是清晰的差异点；
   不要因为加了 `browse_screenshot` 就动摇叙事——把它定位成**诊断工具**，而不是读页面主路径。
2. **可信度是护城河，也是当前短板。** `effect_state`/`page_coverage`/`paint_check` 这套
   「证据链」是别人没有的；但一个 P0 信任边界会让「敢登录」这个前提消失。
   安全修复不是成本，是**让护城河成立**。
3. **下一步的增长点是「可复现的真实世界基准」**，不是更多功能。
   已有 `coverage_probe`（百度 43% / B站 33% / CSDN 60%）和 17 站点 realsites，
   建议把它做成公开的「Agent Browser Benchmark」：读全率、动作成功率、平均 token、
   人工接管次数。这比任何 README 文案都更能说服人。

## 9. 结论

这是一个**判断力远高于平均、结构还没跟上判断力**的项目：

- 它已经解决了 agent 浏览器最难的三件事：**读得懂、点得准、知道有没有生效**；
- 它积累了罕见的「事故 → 机制 → 回归」文化；
- 它当前最大的风险不在功能，而在**信任边界**与**核心类的可演进性**。

如果只做三件事：**关掉页面到控制面的通道、关掉 preload 的 Node eval、把 `PageManager`
和 `extractTree` 各拆出第一刀**。做完这三件，这个项目就从「很聪明的个人项目」
变成「可以放心推荐给别人登录使用的工具」。
