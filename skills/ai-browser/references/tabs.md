# 标签组：每个 agent 一块自己的空间

浏览器里同时有两个人在干活：**用户**，和**每一个 agent**。他们的标签页不混在一起。

## 你的工作页从哪来

第一次真正动手（读树、导航、点击…）而还没指定过目标时，浏览器会给你开一页
**空白标签**并归到你自己的组里。回执里会出现一次：

```json
{"workspace": {"tab": 7, "group": "Agent 2", "created": true, "hint": "..."}}
```

从那以后，**省略 `tab` 就等于打这一页**。这不是"当前显示的那一页" —— 用户切到哪
都不会改变你的目标。

## 三条容易踩的

| 情况 | 会发生什么 |
|---|---|
| 你显式传了 `tab` | 就按你点的来（不会因此把目标钉住；只有 `new` / `switch` 才会改默认目标） |
| 你的页被别人关了 | 下一次调用报 `-32001 ... is gone`，**不会**悄悄换到别人的页上。自己 `new` 一页继续 |
| 你想同时干两件事 | 开多个 tab，并发调用时各自带 `tab`。同一页上的并发写不做协调（值校验会如实报 `input not verified`） |

## 上限

每个组默认 **8 页**（`AI_BROWSER_TAB_LIMIT` 可调）。满了：

```
-32001 your tab group is full (8/8) — close one before opening another
data.tabs = [{tab, url}, ...]
```

（MCP / 工具层收到的这次失败，会以工具结果 `isError: true` + `Error: your tab group is full (8/8) — close one before opening another`
回到你 —— 照着执行就行，不是 JSON-RPC protocol error。）

先把不用的关掉（`browse_tabs {"op":"close","tab":N}`）再开。上限存在的意义不是
刁难：后台运行时没人看得见你的标签页，不设限就会一路开到内存告急。

页面自己弹的窗口（`window.open` / `target=_blank`）不能拒绝 —— 站点的脚本在等它。
那种情况下会顶掉本组里**最久没用、不在人眼前、也没有挂着对话框**的那一页，
并在下一次 `browse_tabs {"op":"list"}` 的 `evicted` 里告诉你。

## 把页面交给用户

用户要用自己的眼睛/手介入时（登录、扫码、滑块、确认支付、看结果）：

```
browse_tabs {"op":"switch","tab":7,"show":true}
```

`switch` 同时做两件事：把这一页顶到用户眼前，并把它设成你的默认目标。
只想让用户**看**、不想改自己的目标，就不要用它 —— 用户自己点标签页就行。

用户点开你那一页只是"看"，**不会**抢走你的目标；你继续在上面操作，他看到的是
实时画面。要避免"我正要输入他却盯着看"的尴尬，就提前说一句。

### 怎么"说一句"——不需要任何工具

**就在你这轮回复里写一句人话，然后结束这一轮、停下等回话。** 例如：

> 请在浏览器窗口里扫这个码，好了回我一句"好了"。

收到"好了"之后再用 `browse_get_tree` 确认状态变了，才继续 —— 别把"用户说好了"
当成"页面真的变了"。

- 本项目**没有** `chat` / `message` / `ask_user` 这类工具，也**没有**"发起一次性会话"
  的功能。去调宿主的临时对话/子对话不会让人去扫码，只会白绕一轮 —— 它是不是用完
  自动关闭，跟你这一轮任务没有任何关系，不用管。
- 交接发生在 agent 的对话里，**浏览器侧零改动**：窗口一直开着，人随时能抢鼠标。
- **人正在操作时不要 `browse_quit`**：它连窗口一起带走，做到一半的全没了。
- 别编造密码/验证码，也别重试注定失败的点击（滑块、风控拦截页）。

## 关于"后台"

```json
{"op": "window", "visible": false}
```

窗口隐藏后所有能力照旧：读树、点击、输入、滚动、上传、对话框、抓包、截图、白屏自检。
单实例启动时也可以用 `AI_BROWSER_START_HIDDEN=1` 让窗口从头就不出现。
用户点 Dock 图标随时叫回来，落在他上次看的那一页，你的任务不受影响。

⚠️ 只有隐藏窗口**不等于**没人看：用户可能正盯着你那一页。别在页面上做会让人
误解的连续操作（比如连续删除）。
